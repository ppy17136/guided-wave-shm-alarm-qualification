# P12-COPV 预注册修订 A2：第4个 burst 频率索引标签映射

## 1. 触发原因与时点

LOCK2 后首次 GPU 冒烟在构建第一个健康模板时停止，错误为：

`ValueError: frequency 260000 Hz has 0 repetitions, expected 3`

停止点位于读取 `MetaData/Index_FrequencyvsRepetition` 后、首次读取
`Data/Raw_Data` 数值之前。没有生成模板、异常分数、阈值、FPR、AUROC或损伤召回，
因此本修订仍属于纯模式映射，不受结果驱动。

对应诊断任务为 `20082.master`，正式任务 `20081.master` 亦在同一点退出。

## 2. 官方H5内部不一致

同一个代表健康H5给出：

- `MetaData/Signal_Frequency_Burst = [60000,120000,180000,260000,300000] Hz`；
- `MetaData/Index_FrequencyvsRepetition` 第二行则为
  `[60000×3,120000×3,180000×3,240000×3,300000×3] Hz`；
- 第一行索引为1至15，且第四组三次重复恰为MATLAB索引10、11、12；
- chirp索引为16、17、18。

因此物理激励清单和原预注册都规定第4个 burst 为260 kHz，而重复索引表将该组误标为240 kHz。

## 3. 唯一允许的执行修订

仅当同时满足以下全部条件时，将索引表中的240 kHz标签解释为260 kHz：

1. 索引表中没有260 kHz重复；
2. 恰有三个240 kHz重复；
3. 三个重复的零基索引恰为9、10、11，即MATLAB索引10、11、12；
4. 其余四频仍各有且仅有三次重复。

任何其他频率缺失、数量变化或索引位置变化均继续报错停止，不作猜测映射。

## 4. 不变内容

- 科学频率仍为60、120、180、260、300 kHz；
- 260 kHz滤波器仍以260 kHz为中心；
- 不新增或删除频率、路径、样本或工况；
- 阈值、支持域、2/3重复确认、3/5频率融合及全部PASS门槛不变；
- LOCK1和原LOCK2保留，另建LOCK2.1，不覆盖历史记录。

## 5. 结论

A2属于官方元数据内部标签冲突的确定性模式映射。它恢复第4个物理burst与其三次重复的关联，
不使用任何波形或损伤结果，允许在LOCK2.1后重新进行同一冻结GPU冒烟。
